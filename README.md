# 钱有数 Sites 体验站

**[打开钱有数线上演示](https://grit888.github.io/qianyoushu-demo/)** · [公开演示仓库](https://github.com/grit888/qianyoushu-demo)

独立浏览器合成数据体验，HTML/CSS/JS 静态站，不连接原项目的本地 FastAPI、数据库或模型接口。用于展示查账、逐笔依据、订阅管理、收支情景估算、异常反馈、组合任务、人工确认与操作记录。

## 当前边界

- 当前 Sites 版本使用合成数据和本机 localStorage；刷新后会恢复本机演示状态。
- 数据管理页支持版本 1 / 2 JSON 本机备份、导入预览、整体替换及本页会话内一次撤销；文件最大 2 MB。保存采用单一完整快照，旧版三键读取迁移后保留原文。CSV支持列映射、逐行校验、来源防重、候选核查和本机追加导入/撤销；平台导出文件可能需先移除说明行。
- 未完成任务、待确认操作、登录会话和云端账本不导出。预览过期、格式错误或保存失败时不替换原数据。
- 备份闭环已通过自动测试；2026-11-17用户完成真实文件选择后，浏览器确认导入、撤销与刷新保留数据均通过，详见 docs/2026-11-17-backup-validation.md。
- 模拟转账和模拟取消订阅不会触发真实金融交易。
- 不包含原项目 `.env`、真实支付宝账单、API key 或私人文件。
- 页面没有连接 DeepSeek；已接 Supabase 邮箱密码登录与独立的云端只读账单面板。云端面板与本机合成账本分开，不自动上传数据。
- 本机开发与公开演示分别构建。

## 本地运行

```powershell
py -3 -m http.server 3088 --bind 127.0.0.1 --directory dist
```

打开 `http://127.0.0.1:3088`。

## GitHub Pages 演示

运行 `python scripts/build_pages_demo.py <新建目录>` 生成 Pages 站点。发布目录根部是 `index.html`，只包含 Git 已跟踪的 `dist/` 静态资源和合成 CSV 示例。构建时移除云端 SDK 与配置引用并收起登录控件。

## Supabase 接入原则

需要先为钱有数创建独立 Supabase 项目，再执行迁移。只使用 publishable/anon key；service_role key 不得进入前端。真实账单上传前应脱敏，并通过 RLS 验证用户隔离。

CSV使用：在数据管理页点击“载入 CSV 示例”或选择文件，固定来源名称并核对列映射后生成预览。金额为正元金额，收支另列；UTF-8/GB18030，最大2 MB、5000条。有来源编号按来源名称+编号识别重复；无编号仅保证同文件同位置不重记，其他相似记录需人工核查。含CSV时JSON备份自动升级为版本2，旧版1仍可读取。详见 docs/2026-11-17-csv-validation.md。

微信支付原始 XLSX 可直接在“数据管理 → 导入账单”选择。浏览器读取单工作表，按原始行号预览商户净消费、已收款转账和排除项。重叠日期沿用同一来源名称可核查重复，旧交易出现退款差异时须人工核对。确认追加后，点“查看这份账单的消费复盘”可看该来源按月的类别和商户排名，并按自己填写的可支配金额、平常消费和储蓄目标试算。支付宝个人对账 CSV 自动识别 UTF-8 / GB18030，以交易状态、收支方向和平台分类导入可识别的已结算交易。关闭、失败及不计收支列入排除项。遇到退款或用途不明的流水，可先确认正常交易，其他记录会保存到「导入待核对」。明确成功的退款可人工关联同一来源的原消费，消费复盘按原消费月份抵扣。其他条目可确认排除或恢复待核对。支付宝适配用合成文件验证。两个平台均由用户选择导出文件。

需要生成 CSV 时也可在本机运行 `python scripts/wechat_xlsx_to_csv.py <原始.xlsx> <输出.csv>`。转换器只导出商户消费：全额退款原交易不导出，部分退款从原交易金额扣除，并要求退款记录的金额和笔数相符；转账、零钱充值/提现及其他收入单独统计但不写入消费 CSV。输出文件应放在代码仓库外，避免提交私人账单。转换结果仍须在数据管理页预览核对，特别是退款记录与原交易是否真的对应；当前只按退款金额和笔数验证，无法从此类导出文件自动证明关联。转换不自动导入或上传。

若要在本机账本同时查看转账流向，可加 `--include-transfers` 生成包含商户净消费与转账的 CSV。转账以“转账”类别保留流入/流出，账单页单列金额；账单流水与情景估算按原始流水口径计算。数据管理的来源核对表将资金总流入/总流出与其中的转账分别展示；核对输入应来自**转换后 CSV**，不能拿原始微信汇总与净额 CSV 直接比较。零钱充值/提现仍不导入。批量分类跳过转账记录，也不能把普通交易改成转账，避免改变统计口径。不要把私人账单直接提交到代码仓库或云端。

批量分类：账单页入口打开独立分类视图，按商户关键词/月份/收支方向预览旧新类别，确认后只修改类别，支持本页会话一次撤销。SIM凭证跳过，不自动改未来账单。搜索范围、跨范围匹配提示和对话新查询后的筛选恢复已浏览器验收。91项测试通过，详见 docs/2026-11-17-classification-validation.md。

周期扣费核对：订阅页支持保存月度计划、同月实际交易人工关联、差额、解除及一次撤销。含计划的备份为版本3，兼容1/2；计划不生成交易，下期日期仅参考。98项测试通过，详见 docs/2026-11-17-recurring-validation.md。

周期计划现在支持修改名称、金额和日期；跨月修改解除旧关联。删除有二次确认，原账单不删除。

分类预算：独立 #workspace/budget 页面按月份和类别设置额度。与消费复盘共用账单范围，支持合看全部导入账单、查看单个来源或切换演示账本。实际支出按原消费月份扣除已确认退款和代付回款，分别显示原额、抵扣、实际支出与剩余额度。每月每类额度在各账单范围共享。删除需确认，支持会话一次撤销。含预算导出v4，旧v1-v3兼容；104项测试通过。

数据管理支持按来源/月度对账汇总及与原CSV汇总人工比较；只读，不凭汇总相同认定账单完整。107项测试通过。

消费复盘的「转账用途标注」支持本人账户互转、亲友往来、代付回款和其他转账。代付回款由用户指向一笔原消费，允许只计入转入的一部分。多笔回款可对应同一消费，累计上限为原消费金额。复盘在原消费月份显示扣减结果，可从明细跳转到回款月份编辑或清除。含用途标注时备份采用版本 5，支持恢复版本 1 至 5。

月结核对：新增 #workspace/monthly-close 页面，按账单范围与月份显示收入、原始消费、已确认退款/回款、实际承担消费、待核对数量和理论余额。月结记录随 JSON 备份版本7保存，兼容版本1至6。点击“生成本月解读”时默认使用本机规则摘要；访客可在公开工作台的“模型配置”中按需直连自己的 OpenAI 兼容服务。

公开演示支持访客在本机填写自己的 OpenAI 兼容模型地址、模型和 API Key。Key 仅保存在访客浏览器，月结解读请求直接发送到访客配置的服务。钱有数不接收或保存 Key；不支持跨域的服务会回退本机规则摘要。
